# 拾光 v0.2 习惯待办 PRD

状态：功能已实现，待真机验收
更新时间：2026-07-26
前置版本：v0.1.0 已发布

## 1. 问题与目标

### 用户事实

用户有每天背单词、看书、锻炼等规律性行动。逐日手动新建待办麻烦，因而希望同一件事能按设定日期自动出现在当天日程中。

用户将其理解为一种特殊待办，而非独立的习惯打卡系统：它和普通待办使用相同的完成操作与排序规则，只是由一条长期有效的规则自动生成。

### 本迭代目标

让用户设置一条习惯待办后，无需每天重复创建，便能在匹配日期的日程中看到并完成它。

### 非目标

- 不做系统提醒、订阅消息或截止时间通知。
- 不做连续打卡、完成统计、习惯评分或习惯历史。
- 不为习惯待办增加与普通待办不同的视觉样式或排序区域。
- 不支持单独修改某一天由习惯生成的待办。

## 2. 入口与页面

### 2.1 入口

首页在“指引”“数据”同一行增加“习惯”入口。现有“新建待办”继续只创建一次性待办，不承担习惯配置。

### 2.2 习惯待办页

页面包含两个区域：

1. **设置新习惯**：填写待办内容、是否设置固定时间，以及重复日期。
2. **已有习惯**：展示内容、重复日期和固定时间；支持修改、删除。

已有习惯不展示当天是否完成。

## 3. 创建规则

| 项目 | 规则 |
| --- | --- |
| 内容 | 必填，作为自动生成待办的内容。 |
| 固定时间 | 可选；设置后，生成的待办为有截止时间待办。未设置时，生成无截止时间待办。 |
| 重复日期 | 支持“每天”或从周一至周日中自由选择若干天。 |
| 生效日期 | 创建后立即生效；即使当天的固定时间已过，当天仍正常展示。 |
| 结束 | 不设置结束日期，直到用户主动删除该习惯。 |

示例：内容为“锻炼”，固定时间为 19:00，选择周一、周三、周五。此后每个匹配日的日程中均自动出现“19:00 锻炼”。

## 4. 日程生成、排序与跨日

- 命中重复日期时，习惯待办自动出现在当天日程中。
- 它与普通待办完全使用既有排序：有截止时间按时间升序；无截止时间按进入当日待办的时间倒序；完成项按完成时间倒序。
- 当天完成只影响当天这一条，不影响之后的自动生成。
- 当天未完成的习惯待办次日直接删除，不滚动为普通无截止时间待办。
- 对于每周指定日期的习惯，未完成项也在次日删除，不等待下一个匹配日。

## 5. 修改与删除

### 5.1 修改

修改内容、固定时间或重复日期时，今天起 7 天内已生成的对应待办同步更新。

若移除某个重复日期，未来七天中不再符合新规则的对应待办删除；若新增日期，未来七天中新增命中的日期立即生成待办。

### 5.2 删除

删除习惯后，今天起 7 天内已经生成的所有对应待办一并删除，不再产生后续待办。

## 6. 数据与实现边界

- 习惯规则是独立数据实体；自动出现的待办需要能追溯其来源习惯。
- 习惯生成与删除必须在领域层或 store 集中处理，页面不能自行复制规则。
- 应用启动时应补齐今天至未来第六天的习惯待办，并去重，避免重复生成。
- 习惯待办不与零碎记录双向关联，除非未来用户从零碎创建习惯的需求另行确认。

## 7. 验收

1. 可创建每天、每周指定日期的习惯待办，固定时间可选。
2. 匹配日期的当天待办可见，且排序与普通待办一致。
3. 未完成习惯待办次日消失，不触发普通待办的跨日滚动。
4. 修改内容、时间、重复日期时，今天和未来七天对应待办同步正确。
5. 删除习惯时，今天起 7 天内对应待办全部清除。
6. 习惯列表只展示内容、重复日期、固定时间，并支持修改与删除。
7. 全程不请求或发送系统通知。
