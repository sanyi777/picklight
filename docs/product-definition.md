# 拾光 TimeGleam Phase 0 产品定义

## 1. 产品定位

拾光是一款小程序优先、本地优先的私人注意力助理。

它不是单纯的日程工具、备忘录或番茄钟，而是一个随时可打开的移动注意力工作台：接住用户零碎的思绪，帮助用户看清今天的安排和重点，用番茄钟保护工作时间，并在需要时把用户拉回当前锚点。

第一版不做主动提醒、不做情绪陪伴、不做云同步、不做 AI 自动分析。它先成为一个安静、可靠、低负担的本地工具。

## 2. 产品核心

拾光围绕四个动作展开：

1. 承接零碎思绪
2. 管理今日锚点
3. 用番茄钟保护工作时间
4. 让待办、复盘和专注记录自然沉淀

核心关系：

```text
待办管理时间和行动
主锚点管理注意力
番茄钟保护锚点
捕捉承接偏离锚点的杂念
```

## 3. 目标用户

第一版面向个人知识工作者、自我驱动学习者、自由职业者和需要管理大量零碎想法的人。

他们的典型困境：

- 一天中有很多想法、待办、灵感和杂念，但容易散落在聊天、便签和脑子里。
- 有日程安排，但真正做事时容易偏离当前最重要的方向。
- 想提高注意力，但不希望使用过度复杂或强约束的效率系统。
- 希望工具像私人助理一样接住信息、整理状态、帮助回到当下。

## 4. 小程序优先原则

第一版只做微信小程序，不再同时推进 Windows / PC 端。

做出这个收敛的原因：

- 小程序更符合“随时打开、快速记录、快速回到当下”的使用场景。
- 当前 PC 端 demo 效果不理想，继续双端并行会稀释产品判断和开发精力。
- 第一版的核心价值不依赖桌面端能力，先把移动端闭环打磨成熟更重要。

小程序第一版强调：

- 随时打开
- 快速捕捉
- 查看今日
- 轻量编辑
- 轻量专注
- 本地保存

第一版不做：

- Windows / PC 客户端
- 双端功能一致
- 多端同步
- 桌面快捷键
- 桌面托盘
- 宽屏布局

## 5. 第一版 MVP 范围

### 做

- 小程序本地数据存储
- 无账号
- 无同步
- 快速捕捉
- 可编辑分类
- 今日重点
- 当前锚点
- 专注锚点
- 番茄钟
- 分心记录
- 今日待办
- 未来 7 天周视图
- 轻量本地备份方案评估

### 不做

- 主动提醒
- 情绪陪伴
- AI 自动分析
- 云同步
- 多端实时同步
- PC 端
- 复杂统计仪表盘
- 复杂标签系统
- 重复待办
- 复杂日历拖拽
- 团队协作

## 6. 核心概念定义

### 待办

待办回答：今天或这周有哪些事情需要被看见、推进或完成？

在第一版中，日程与待办合并为同一个概念，后续统一称为“待办”。待办可以有日期和时间，也可以只有日期。它同时承担传统待办和轻量日程的职责。

第一版字段：

```text
id
date
time
content
completed
rolledOverFrom
createdAt
updatedAt
```

第一版视图：

- 日视图：查看某一天所有待办
- 周视图：总览未来 7 天要做的事

继承规则：

- 未完成待办会自动继承到下一天。
- 继承不是复制新待办，而是将原待办的 `date` 滚动到下一天。
- 原始创建时间保留，便于后续分析拖延和延期。

第一版不做：

- 重复事项
- 主动提醒
- 外部日历订阅
- 拖拽排期

### 今日重点

今日重点回答：今天最重要的几件事是什么？

一天最多可以有 2 个今日重点。今日重点不一定有固定时间，它表达优先级和方向。

示例：

```text
完成拾光 Phase 0 产品定义
整理明天会议材料
```

### 当前锚点

当前锚点回答：我现在正在守住哪一个重点？

同一时刻只能有 1 个当前锚点。它可以来自今日重点、待办、零碎内容，也可以手动新建。

当前锚点是首页和专注页最重要的状态。它让用户一打开拾光就知道自己现在应该回到哪里。

### 专注锚点

专注锚点回答：这一轮番茄钟具体要完成什么？

每一轮番茄钟可以有 1 个专注锚点。开始番茄钟时，如果已经有当前锚点，默认继承当前锚点；用户也可以单独改写。

示例：

```text
当前锚点：完成拾光 Phase 0
专注锚点：写清楚锚点和待办的边界
```

### 捕捉

捕捉回答：我现在脑子里出现了什么，需要先放下来？

捕捉输入时需要选择分类。分类可以之后添加、修改或删除。

第一版默认分类：

```text
灵感
随想
待办
分心
复盘
```

分类规则：

- 灵感：突然出现的想法、方案、创意。
- 随想：暂时不需要行动的零碎念头。
- 待办：输入后自动进入今日待办。
- 分心：专注中出现的干扰项。
- 复盘：对当天状态、执行、偏差的记录。

第一版先只做分类，不做多标签系统。标签可以作为后续增强能力。

## 7. 捕捉内容的流转

捕捉内容不是终点，而是一个分类后的零碎池。

一条捕捉可以在后续变成：

- 普通记录：保留在捕捉列表中
- 待办：分类为待办后自动进入今日待办
- 今日重点：设为今天的重要方向之一
- 当前锚点：立即成为当前注意力目标
- 分心记录：番茄钟中快速记录的干扰项
- 复盘素材：归档在零碎-复盘中

第一版要求用户在输入时选择分类，但分类可以随时修改。

推荐交互：

```text
输入捕捉
  -> 选择分类
  -> 如果分类为待办，自动进入今日待办
  -> 可设为今日重点
  -> 可设为当前锚点
```

## 8. 今日首页结构

今日首页是第一版的核心页面。

它应该让用户在 5 秒内回答三个问题：

1. 我今天有哪些待办？
2. 我今天最重要的是什么？
3. 我现在应该回到哪里？

建议结构：

```text
顶部：今天日期

当前锚点卡片
- 当前正在推进的主锚点
- 开始番茄钟按钮
- 更换锚点入口

当日主锚点
- 最多 2 个
- 手动进度条
- 可设为当前锚点
- 可标记完成

今日待办
- 按时间排序
- 可标记完成
- 可进入周视图

快速捕捉
- 单行输入框或悬浮输入入口
- 保存后默认进入捕捉池

今日摘要
- 今日捕捉数量
- 今日完成待办数量
- 今日专注轮数或分钟数
```

首页不应该堆满统计图。第一版只放轻量摘要，让用户保持行动感。

## 9. 专注页结构

专注页围绕专注锚点和番茄钟展开。

建议结构：

```text
专注锚点
- 默认继承当前锚点
- 可编辑

主锚点进度
- 第一版只能手动拖动进度条
- 不根据待办完成数自动计算

番茄钟
- 可手动设置时间
- 可填写本轮要完成的小事
- 开始
- 暂停
- 重置
- 完成记录

分心捕捉
- 专注中快速记录杂念
- 默认分类为分心
- 不打断计时流程
```

第一版不做完成提醒。番茄钟完成时可以只在界面内显示完成状态。

## 10. 捕捉页结构

捕捉页是用户的思绪收纳箱。

建议结构：

```text
快速输入区
- 输入时选择分类
- 支持保存后修改分类

筛选区
- 全部
- 灵感
- 随想
- 待办
- 分心
- 复盘

列表区
- 内容
- 分类
- 创建时间
- 快捷操作：设重点 / 设锚点 / 删除
```

第一版可以先不做全文搜索。若实现成本低，可以加入基础关键词搜索；复杂搜索可以后置。

## 11. 四个主导航

第一版底部导航包含四个入口：

```text
主页
零碎
日程
专注
```

### 主页

主页是今日状态入口，负责快速回到当下。

包含：

- 今日待办摘要
- 当日主锚点，最多 2 个
- 快速捕捉零碎想法入口
- 快速开启番茄钟入口

### 零碎

零碎是分类后的思绪收纳箱。

包含：

- 记录想法的输入框
- 分类入口：灵感、随想、待办、分心、复盘
- 分类列表

规则：

- 输入时需要选择分类。
- 选择“待办”后，内容自动进入今日待办。
- 从日程页输入的复盘自动归档到零碎-复盘。

### 日程

日程页展示和管理待办。虽然页面名称保留“日程”，但底层概念统一叫“待办”。

包含：

- 今日待办
- 当日主锚点
- 未来 7 天周视图
- 当日复盘输入

规则：

- 未完成待办会滚动到下一天。
- 日程页输入的当日复盘会自动归档到零碎-复盘。

### 专注

专注页是执行现场。

包含：

- 当日主锚点
- 主锚点手动进度条
- 番茄钟
- 本轮要完成的小事

规则：

- 番茄钟时间可以手动设置。
- 每轮番茄钟必须有一个“小事”描述，用来说明这段时间要完成什么。

## 12. 后续路线

### Phase 1：本地 MVP

- 小程序项目初始化
- 主页
- 零碎
- 待办日视图和周视图
- 当日主锚点
- 当前锚点
- 番茄钟
- 分心记录
- 小程序本地存储

### Phase 2：数据整理能力

- 轻量备份方案
- 基础搜索
- 零碎转重点
- 零碎转锚点
- 分类管理

### Phase 3：体验增强

- 统计概览
- 专注历史
- 项目进度
- 更好的小程序移动交互

### Phase 4：后续平台评估

- 云同步方案评估
- 账号系统评估
- PC / Windows 是否重启评估
- 如果重启 PC 端，需要基于小程序成熟后的信息架构重新设计

## 13. 未决问题

这些问题不阻塞第一版，但需要后续确认：

1. 第一版是否需要“项目”概念，还是等核心闭环稳定后再加入？
2. 分类是否允许用户完全自定义名称和颜色？
3. 小程序本地存储容量是否足够第一版使用？
4. 第一版是否提供手动备份，还是只依赖微信小程序本地缓存？
5. 番茄钟在小程序后台状态下如何处理，第一版是否只保证前台计时体验？
